# 从岗位需求长出一套概念卡片

**卡片不是从教材目录里抄的，是从岗位需求里长出来的。**

这套流程解决一个具体问题：你知道该学什么方向，但不知道该学哪些概念、学到什么深度。
招聘 JD 恰好是市场给出的答案——**被 N 个不同岗位提到的概念，就是必须会的；只出现一次的，可以缓一缓。**

产出物是一个纯静态站点：加到手机主屏，每天推几张新卡 + 到期复习，SM-2 调度，断网可开。

## 二 · 抓：拿到带正文的岗位

直接用 `boss-scrape`，产出 `data/<prefix>_detail.json`（本技能只认这个文件）。

```bash
python ../boss-scrape/scripts/scraper.py \
  --keywords "感知算法,多传感器融合,激光雷达算法,具身智能,SLAM" \
  --cities "上海,南京,苏州" \
  --strong "感知,融合,SLAM,标定,雷达,点云,机器人" \
  --weak   "算法,嵌入式,模型,部署" \
  --noise  "销售,客服,实习助理,培训讲师" \
  --pages 3 --max-details 300 --out data
```

**关键词怎么定**：4–9 组，覆盖「同一件事的不同叫法」，不要堆近义词。
目标领域的关键词写法，直接决定抽词质量——用招聘市场上真实的岗位名，别用学术名词。
例：要学「雷达信号处理」，抓「雷达算法」「毫米波雷达」比抓「FMCW 信号处理」有效得多。

## 三 · 抽：哪些概念值得做成卡片

```bash
python scripts/extract_terms.py --input data/xxx_detail.json --out data/terms.json --top 60
```

先看终端表格，再看 `terms.json`。**这一步的产出是候选，不是结论**，必须人工/模型过一遍。

### 3.1 为什么按「提及岗位数」排序，不按词频

同一个 JD 里出现 20 次的概念，可能只是那家公司的口头习惯；
20 个 JD 各出现 1 次的概念，才是这个岗位的公共必修课。

所以脚本统计的是 **distinct job count**，词频只用来打破平手。

### 3.2 脚本替你挡掉的四类噪音

这些都是实测踩出来的，不是理论推导：

| 噪音 | 实测数据 | 处理 |
|---|---|---|
| **反爬水印插在词内部** | 153 条岗位里 `kanzhun` 出现 21 次，把「抖音」切成了「抖kanzhun音」 | 删水印后**不做空格替换**，让被切开的词自动复原 |
| **康熙部首冒充汉字** | 同样 153 条里有 **532 个** `⽇`(U+2F47) 这类字符，肉眼几乎看不出 | `NFKC` 归一化还原成 `日`，否则术语永远匹配不上 |
| **跨词边界的碎片** | `数据分`（来自 数据\|分析）、`沟通协`（来自 沟通\|协调） | 分词边界一致率 < 0.75 直接丢 |
| **单侧固定的碎片** | `据安全`（左边永远是「数」）、`安全工`（右边永远是「程」） | 左右邻接字熵 < 1.0 bit 丢 |

实测漏斗（153 条数据安全岗）：
`6820 个候选 → 熵过滤剩 1036 → 边界过滤剩 725 → 虚词词性剩 698 → top 60 输出`

### 3.3 拿到表格后怎么筛

按这个顺序看，**留下能回答「原理是什么」的词**：

1. **先删掉泛能力词**：合规、审核、整改这类流程词，除非目标岗位就是做流程
2. **保留中英混排的硬词**：`TF2`、`CAN FD`、`ISO 26262`、`ros2_control`、`VLA`
3. **层级别搞错**：`数据安全` 是分类，`威胁建模` 才是能做成卡的概念
4. **一条判据**：如果这个词你只能写出「它很重要」，写不出三条原理，就不要做卡

`--min-jobs` 的用法：岗位样本 < 50 时用 2，100~300 用 3，> 300 用 4~5。

## 四 · 写：八字段，一张卡一个概念

**规范全文在 `references/card_writing.md`，动笔前必须读。** 这里只给判据。

| 字段 | 回答什么 | 常见错误 |
|---|---|---|
| `term` | 叫什么 | 带括号注释（英文放 `en`） |
| `en` | 英文名/缩写 | 机翻，不是岗位里用的那个写法 |
| `one` | 是什么（一句话） | 写成用途而非定义 |
| `jd` | **为什么考它** | 写「该岗位要求掌握」（等于没写） |
| `pts` | 3~5 条原理，至少一条带数值 | 全是定性描述，背了用不上 |
| `use` | 工程上怎么用 | 和 `one` 重复 |
| `trap` | 容易踩的坑 | 写「注意安全」（正确的废话） |

### 4.1 写卡时唯一允许的信息源

`terms.json` 里每个候选都带 `samples`——**原文片段**。写 `jd` 和 `trap` 必须基于它。

```json
"term": "数据分类分级", "jobs": 43,
"samples": ["参与数据分类分级梳理及合规性检查",
            "主导企业数据分类分级体系搭建，输出数据地图"]
```

从样例能直接读出「岗位原话怎么说的」，`jd` 字段就有据可依，不会写成「该岗位需要掌握本概念」。

### 4.2 铁律

- **错概念比没概念更贵。** 拿不准的原理宁可不写，或写成「常见说法」并标注
- **每天最多 8 张。** 10 张以上当天就背不完，第二天欠账会直接劝退
- **一个概念一张卡。** 「EKF 与 UKF」应该拆成两张

## 五 · 入池：校验 + 幂等写入

固定站点（`ccccty/study`）已经自带上这一步，在仓库根直接跑 `python tools/merge_cards.py <候选卡> [--dry-run]` 即可，**不用 `--cards` 参数**（路径写死在仓库里）。

新起一个站时，用本技能自带的脚本：

```bash
# 先看会新增什么、拒收什么
python scripts/merge_cards.py --cards ../my-study/cards.json \
    --input cands/2026-10-26.json --dry-run

# 确认后正式写入（自动备份 cards.json.bak）
python scripts/merge_cards.py --cards ../my-study/cards.json --input cands/2026-10-26.json
```

**这个脚本的价值是拒收，不是写文件。** 四道闸门：

1. 结构：八字段齐全，长度在合理区间
2. 空话：`jd` 命中「该岗位要求掌握」、`trap` 命中「注意安全」→ 拒收
3. 可量化：`pts` 里一条都不含数值/单位/量级 → 拒收
4. 去重：术语归一化后比对，重复跳过（**幂等，可以反复跑**）

卡片 id 由**术语哈希**生成，不是数组下标。
理由很实际：`cards.json` 顺序一变，手机上已有的复习进度就会错位到别的卡——
你以为在复习 A，实际记录的是 B 的进度，而且完全无法察觉。

候选文件格式（`cands/日期.json`）：

```json
{
  "date": "2026-10-26",
  "cats": {"sec": {"name": "数据安全", "color": "#1b4b8f", "scene": "数据安全与合规岗的底座"}},
  "cards": [
    {"cat": "sec", "term": "威胁建模", "en": "threat modeling",
     "one": "…", "jd": "…", "pts": ["…", "…", "…"], "use": "…", "trap": "…",
     "evidence": {"jobs": 14, "sample": "具备基本的威胁建模与风险评估思维"}}
  ]
}
```

`cats` 可以先不注册，`merge_cards.py` 会自动补上并按色板分配颜色。

## 六 · 起站：一个领域一个站

```bash
python scripts/build_site.py --out ../../数据安全-study \
    --title "数据安全 · 每日一推" --desc "数据安全与合规岗的高频概念，每天 8 张" --short "数安卡"
```

生成纯静态站点：`index.html`（引擎）+ `cards.json`（**唯一数据源**）+ `sw.js` + `manifest.webmanifest` + `icons/`。

**引擎里没有任何领域内容。** 换领域就是换一份 `cards.json`，代码一行不用改。

本地预览（`file://` 读不到 cards.json，必须走 http）：

`git init → push → Settings/Pages 选 main → 手机打开 → 添加到主屏幕`。

## 七 · 每天循环（可挂自动化）

```
08:40 抓当天岗位（boss-scrape）
   ↓
抽词 extract_terms.py --known 已有 cards.json   ← 这个参数会标出哪些已入池
   ↓
挑 3~8 个缺口概念 → 按八字段写卡（必须用 samples 做依据）
   ↓
merge_cards.py --dry-run 看拒收原因 → 正式写入
   ↓
git commit cards.json && git push     ← 手机打开即拿到新卡
```

挂在固定站点上时，全流程都在 `E:/工作/个人简介/study` 一个目录里完成，**只有一次 commit 一次 push**，不碰任何其他仓库。

手机端**不需要做任何更新操作**：页面每次打开都带 `?t=时间戳` 拉 `cards.json`。
只有改了 `index.html` 本身才需点「刷新题库」。

### 站点已存在时怎么追加

`--known` 让抽词直接告诉你哪些已经做过了：

```bash
python scripts/extract_terms.py --input data --known ../my-study/cards.json --top 60
```

表格里带「(已入池)」的就是不用再做的。

## 九 · 三个坑（都会让你白干半天）

**1. 双击 `index.html` 打开是空白的。**
`file://` 协议下 `fetch('cards.json')` 被浏览器拦掉，页面只会显示「没读到 cards.json」。
这不是 bug，是安全策略。验证站点必须起 http 服务，或直接看线上地址。

**2. 中文描述的乱码不是乱码。**
`⽇`、`⼯`、`⽤` 是康熙部首，不是汉字，肉眼几乎分不出。但 `'⽇' !== '日'`，
所有字符串匹配都会失败。`extract_terms.py` 用 NFKC 处理了，**自己写脚本时别忘**。

**3. 卡片写多了会崩。**
每天 8 张是实测能坚持的上限（约 4 分钟）。一次灌 50 张，第二天待复习 40 张，
第三天就放弃了。慢就是快。
