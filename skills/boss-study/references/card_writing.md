# 写卡规范：八字段

一张卡只讲一个概念，八个字段各回答一个问题。**没有 `jd` 的卡等于半张废卡**——
你会背下定义，但说不出为什么考它，面试时依然用不上。

---

## 字段表

| 字段 | 类型 | 长度 | 回答的问题 | 必填 |
|---|---|---|---|---|
| `cat` | string | 已在 `cats` 注册 | 属于哪个分类 | ✅ |
| `term` | string | 2~40 | 它叫什么 | ✅ |
| `en` | string | 0~80 | 英文名或缩写 | ⬜ |
| `one` | string | 10~140 | **是什么**（一句话定义） | ✅ |
| `jd` | string | 15~220 | **为什么考它**（岗位场景） | ✅ |
| `pts` | string[] | 3~5 条 | **怎么运作**（原理与要点） | ✅ |
| `use` | string | 10~220 | **怎么用**（工程动作） | ✅ |
| `trap` | string | 12~220 | **会怎么错**（具体的坑） | ✅ |

硬性约束（`merge_cards.py` 会自动拦）：`pts` 至少一条含数值/单位/量级；`term` 不带括号注释。

---

## 逐字段写法

### `one` — 一句话定义

只回答「是什么」。判断标准：**把它单独发给同事，他能立刻知道你在说哪一层的技术**。

- ✅ `用激光测距加扫描，直接得到目标距离并生成三维点云的主动传感器。`
- ❌ `激光雷达非常重要，在自动驾驶中被广泛使用。`（评价，不是定义）
- ❌ `用于感知周围环境。`（太泛，相机毫米波都成立）

### `jd` — 岗位场景

**这是最容易写废的字段，也是决定卡片有用的字段。**

两句话的写法：第一句还原岗位原话，第二句说面试/评审会追到哪一层。

- ✅ `岗位高频表述：负责数据分类分级梳理与合规性检查。面试会追问分级依据用哪套标准、分错了怎么补救。`
- ✅ `多机项目的面试题：多台设备同时运行怎么避免话题互相干扰。标准答案就是域隔离。`
- ❌ `该岗位要求掌握本概念。`（零信息量）
- ❌ `这是机器人领域的重要概念。`（空话）
- ❌ `某公司月薪 30K 的岗位需要这个。`（不许编造公司名与薪资）

不合格的 `jd` 会被 `merge_cards.py` 拦下来，命中词表见脚本里的 `JD_BANNED`。

### `pts` — 原理与要点

3~5 条，**至少一条必须是可量化的**：具体数值、公式、量级、换算关系。

为什么强制要求数值：只有定性描述的卡片，背完还是回答不了「为什么这个参数是这个值」。

- ✅ `77GHz 带宽 4~5GHz，距离分辨率约 c/2B，1GHz 带宽对应 15cm`
- ✅ `需求阶段修复缺陷的成本约为上线后的 1/100`
- ❌ `带宽越大分辨率越高`（对，但没信息量，等于没说）
- ❌ `需要注意参数配置`（废话）

其余要点写「运作机制」和「分类/路线」，不要写优点清单。

### `use` — 工程上怎么用

写**具体动作**：在哪个环节、对什么对象、做什么操作。

- ✅ `车端做三维障碍物检测、可行驶区域提取，进融合链路前必须先完成外参标定与时间同步。`
- ❌ `用于感知。`（没有动作）

### `trap` — 容易踩的坑

**必须是具体、可验证、能引起共鸣的坑。** 判断标准：老工程师看到会点头，新人看到会「啊，我踩过」。

- ✅ `雷达横穿目标的径向速度接近 0，会被当静止物滤掉，这是 AEB 漏检的经典原因。`
- ✅ `只改 yaml 不改 launch 里的默认值，会出现「改了没生效」，而且日志里看不出任何异常。`
- ❌ `注意安全。`（不是坑）
- ❌ `参数要调好。`（不是坑）
- ❌ `需要一定经验。`（不是坑）

## 卡片的四层逻辑

翻面后从上到下是这样一条线，**任何一层缺失，这张卡的价值都会掉一半**：

```
① 是什么      one
② 为什么考    jd      ← 把概念和求职目标绑起来
③ 怎么运作    pts     ← 带数值，才背得进脑子
④ 怎么错      trap    ← 面试拉开差距的地方
```

`use` 是 ③ 和 ④ 之间的桥：知道原理，还要知道在哪个环节动手。

## 完整示例

### 例 1 · 硬件与信号

```json
{
  "cat": "radar",
  "term": "最大不模糊速度",
  "en": "max unambiguous velocity",
  "one": "FMCW 雷达能唯一测出的最大径向速度，由相邻 chirp 的间隔决定，超过就会速度模糊。",
  "jd": "岗位高频表述：熟悉雷达信号处理，能处理速度模糊。面试会追问解模糊为什么要改 chirp 周期而不是改带宽。",
  "pts": [
    "v_max = λ / (4·Tc)，Tc 是同一根天线上相邻 chirp 的起始间隔，77GHz 时 λ≈3.9mm",
    "Tc 取 50μs 时 v_max≈19.5m/s（约 70km/h），高速场景必须加密 chirp",
    "速度模糊表现为目标速度折叠，实测中常见「前车突然反向加速」的假象",
    "解模糊靠多组不同 Tc 的 chirp 配对，用余数一致性反推真实速度"
  ],
  "use": "设计波形时先按目标场景最高车速反算 Tc，再留 20%~30% 余量给测量噪声。",
  "trap": "只按最高车速算 v_max，忘了对向车道的相对速度是两车之和——高速上 120+120 就能翻倍超出量程。"
}
```

### 例 2 · 岗位驱动型（非硬技术）

```json
{
  "cat": "sec",
  "term": "数据分类分级",
  "en": "data classification and grading",
  "one": "按敏感程度和影响范围给数据打上等级标签，安全措施跟着等级走。",
  "jd": "岗位高频表述：负责数据分类分级梳理与合规性检查。面试会追问分级依据用哪套标准、分错了怎么补救。",
  "pts": [
    "分级通常参照国标 GB/T 43697，把数据分为核心、重要、一般三级",
    "一般数据再按 1 到 4 级细分，等级决定加密与访问控制强度",
    "分级不是一次性工程，业务新增字段要回流到分级清单"
  ],
  "use": "做数据地图、定访问控制策略、判断哪些数据能出境。",
  "trap": "只按字段名分级不看业务含义，同一个「身份证号」在测试库里是假数据、生产库里是敏感数据，一刀切会导致生产库管控不足。"
}
```

## 常见退稿原因

| 症状 | 原因 | 改法 |
|---|---|---|
| `one` 和 `use` 读起来一样 | 把用途当成了定义 | `one` 只写「是什么」，用途挪到 `use` |
| `pts` 全是「很重要/要重视」 | 没查到机理就动笔 | 去 `terms.json` 的 `samples` 里找原文，找不到就放弃这张卡 |
| `trap` 像免责声明 | 没踩过，靠想象 | 只写你能说清触发条件的坑 |
| 一张卡塞了两个概念 | 图省事 | 拆开，各写一张 |
| `jd` 全是「该岗位要求」 | 没读 JD 原文 | 抄一句 `samples` 里的原话，再补面试追问点 |
