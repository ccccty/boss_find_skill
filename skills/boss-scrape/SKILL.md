# BOSS 直聘岗位抓取

脚本已随 skill 提供，**不要现场重新生成脚本**——直接用 `scripts/scraper.py`。

脚本位置：`scripts/scraper.py`（同目录还有 `cities.py`，负责城市名 → 城市编码）。

## 前置检测

```bash
python -c "from cloakbrowser import launch; print('ENV:OK')" 2>&1
```

- 有 `ENV:OK` → 继续
- 报错 → 告诉用户先说「配置boss抓取」初始化环境，**不要继续**

## 参数获取

从用户话里提取，缺的主动问：

| 参数 | 说明 | 默认 |
|---|---|---|
| 关键词 | 岗位搜索词，可多组 | 必填 |
| 城市 | 目标城市，可多城 | 必填 |
| 详情上限 | 抓多少条详情 | 400 |

### 关键词怎么拓

单关键词在 BOSS 上最多约 90 条。**但不要把近义词堆成十个**——真正的问题是平台召回质量，不是数量：

| 用户说 | 建议 |
|---|---|
| 产品经理 | `产品经理,产品总监,B端产品经理` |
| Java | `Java后端,Java开发,Java工程师` |
| 港航 | `港航,港口航道,水利工程,水工`（同专业的不同叫法） |
| 会计 | `会计,总账会计,成本会计,财务主管` |

经验：**4–9 组词足够**。再加，返回的多是平台推的无关岗位，白花详情配额。

### 城市

城市名用简称（`苏州` 不是 `苏州市`）。脚本内置常见城市，其余自动查官方接口并缓存到 `~/.boss-skill/cities.json`。查不到会直接报错并提示补编码，不会静默跳过。

## 运行

```bash
# 基本用法
python scripts/scraper.py --keywords "港航,港口航道" --cities "上海,成都" --strong "港航,港口,航道,水运"

# 加城市 + 收紧相关性
python scripts/scraper.py \
  --keywords "水利工程,智慧水利,水文" \
  --cities "上海,南京,成都,宜宾,自贡" \
  --strong "水利,水工,水文,水务,港航,港口,航道" \
  --weak   "算法,模型,信息化,数字孪生,遥感,GIS" \
  --noise  "送水,防水,销售,客服,司机" \
  --pages 4 --max-details 400 --out data
```

| 参数 | 作用 |
|---|---|
| `--strong` | 岗位名命中即一级优先（真正对口的词） |
| `--weak` | 岗位名命中则二级优先（技术类词，需 JD 复核） |
| `--noise` | 岗位名命中直接丢弃（关键词误命中的噪音） |
| `--pages` | 每个关键词×城市滚动几轮，每轮约 15 条 |
| `--no-filter` | 不做相关性过滤，全量抓详情（数据量大时慎用） |
| `--reuse-list` | 复用上次的 `*_list_raw.json`，只重跑过滤+详情 |
| `--headless` | 无头模式。**首次登录不要用**，否则没法扫码 |

首次运行会弹浏览器要登录（最多等 10 分钟）；登录态存 `data/cookies.json`，之后自动复用，不用重复扫码。未登录会**直接中止**而不是抓一堆空数据。

## 为什么是两阶段

```
阶段一：9 关键词 × 5 城 → 列表 1633 条（只有标题/公司/地点，很便宜）
        ↓ 按「目标城市 + 相关性」过滤排序
        一级 477 + 二级 162
        ↓ 截断到上限
阶段二：只对这 550 条抓详情（薪资/JD/规模，很贵）
```

对比「全量抓详情」：**详情请求量降低 60%+，总耗时从 2 小时压到 1 小时**。
列表阶段落的 `*_list_raw.json` 可复用，换过滤条件重跑不用再翻页。

## 三个必须知道的平台坑

**1. `city` 参数会失效。** 目标城市岗位少时，BOSS 会返回全国岗位。实测：搜「宜宾·海洋工程」回来 75 条，全是外地。所以脚本**必须按 `location` 字段二次过滤**，不要相信 URL 里的 city。

**2. 冷门关键词会被降级成泛岗位。** 搜「航道工程」可能返回「AI 算法工程师」「酒店前台」——平台拿泛「工程师」结果填充。这类噪音占过 272/439，只能靠 `--strong/--noise` 在列表阶段就剔掉。

**3. 关键词会误命中。** `水工` → 「送水工」「防水工」「消防水工」；`会计` → 「电话销售」。把这些写进 `--noise`。

## 输出

| 文件 | 内容 |
|---|---|
| `<prefix>_list_raw.json` | 阶段一列表原始数据（可复用） |
| `<prefix>_detail.json` | 完整岗位（含薪资/JD），给 boss-analyze 用 |
| `<prefix>_detail.csv` | 同上，Excel 友好 |
| `<prefix>_stats.json` | 每个关键词×城市的收集量 |
| `cookies.json` | 登录态 |

详情页每 25 条落一次盘，中途断了不用重跑。

## 限流处理

脚本内建：连续 3 次报错 → 等 30–90 秒 → 回首页刷新 → 继续。真正的登录失效（`DISCONNECTED` 持续）只能人工扫码。

不建议把 `--pages` 调到 6 以上，也不建议一天内反复跑同一组关键词，容易被要求验证。

## 完成后报告

各关键词采集量、去重后条数、薪资获取成功率、文件位置，然后提示可以用 `boss-analyze` 出报告。

## 合规

仅供个人求职研究。抓取的是登录后可见的公开岗位信息，不要用于商业采集、转卖数据或高频轮询。

## Windows 速查

| 场景 | Windows（Git Bash / CMD） | macOS / Linux |
|---|---|---|
| 激活 venv | `source .venv/Scripts/activate` | `source .venv/bin/activate` |
| 直接调用解释器 | `.venv/Scripts/python.exe scripts/scraper.py ...` | `.venv/bin/python scripts/scraper.py ...` |
| 建 venv | `python -m venv .venv`（Windows 没有 `python3`） | `python3 -m venv .venv` |

路径一律用正斜杠 `/`，Git Bash 也能识别 `E:/工作/boss-jobs` 这类路径；`data/`、`reports/` 都相对于**当前工作目录**，三个 skill 要在同一个项目目录下跑。
